# 검수·비교·듣기 페이지

사용자에게 무엇을 고르게 하거나 검수받으려고 HTML 페이지를 만들 때 연다. 언제 페이지로 보여 줄지를 다른 스킬·지침이 정해 두었으면 그것을 따르고, 없으면 0절을 따른다.

**이 문서에서 쓰는 말**
- **페이지 종류** = 2.2–2.5의 네 가지 모양(고르기 · 바뀐 것 검수 · 계획 · 결과·설명). 「꼴」도 같은 뜻
- **카드** = 페이지 안의 상자 하나. 보기 하나(고르기) 또는 바뀐 곳 하나(검수)
- **칸** = 사용자가 답을 넣는 자리(버튼·메모 입력란). 2.3 「칸이 많은 대상」의 칸만 표의 열(DB 컬럼)
- **넣기 / 빼기** = 바뀐 곳 하나를 승인(반영) / 거절하는 버튼
- **고침 N** = 사용자 평을 받아 다시 고친 N번째 판. 같은 페이지 맨 위에 덧붙인다

## 0. 언제 페이지로 보여 주나

| 이럴 때 | 페이지 |
|---|---|
| 사용자가 「페이지로」「비교로」「전후로」 보여 달라고 함 | 만든다 |
| 보기가 눈으로 보거나 들어야 갈림 (화면 배치·모양, 그림·장면, 소리·목소리) | 만든다 — 보기마다 실제 모양으로 |
| 여러 곳을 바꾼 것을 승인받음 (문서·설정·스키마·노드 몇 곳 이상) | 만든다 — 2.3 |
| 결정에 쓰는 결과가 그림·그래프·여러 화면 | 만든다 — 2.5 |
| 보기가 글로만 갈림 (값·방식·순서), 바뀐 곳이 한두 줄 | 만들지 않는다 — 채팅의 표나 −/+ 줄로 |

페이지를 만들면 채팅에는 결론·추천 한 줄과 페이지 주소만 쓴다. 같은 내용을 채팅에 다시 늘어놓지 않는다.

## 1. 무엇을 보여 줄 때 어느 종류

갈래는 「무엇이 바뀌거나 무엇을 고르나」로 나눈다. 다른 스킬에 페이지를 만드는 전용 도구가 있으면 그것을 쓰고, 꼴은 2절을 따른다.

| 무엇 | 종류 |
|---|---|
| 후보 고르기 (시안·그림·목소리·효과음·방식·모델) | 2.2 고르기 |
| 문서·노드·스키마·코드·화면이 바뀜 (새로·고침·옮김·지움·합치기) | 2.3 바뀐 것 검수 (칸이 많은 표는 2.3 「칸이 많은 대상」) |
| 편집본·고친 판에서 바뀐 곳 | 2.3 바뀐 것 검수 (구간 시간 같이) |
| 이름 가린 비교 (모델·초고 — 추천 표시 없음) | 2.2 고르기, 추천만 뺌 |
| 작업 순서·단계, 할 일 묶음 | 2.4 계획 (시험 중) |
| 조사 결과·분석·보고 한 장, 숫자 추이 | 2.5 결과·설명 |
| 분류·거르기 결과 | 2.5 결과·설명 (사용자가 항목을 되살리거나 빼게 하려면 2.3 「넣기 / 빼기」 버튼을 빌림) |

## 2. 페이지 표준

페이지는 아래 네 종류(2.2–2.5) 중 하나(섞이면 절마다 그 종류를 따른다). 2.1은 모든 페이지 공통, 2.6은 종류가 아니라 고르는 칸이 있는 페이지의 공통 기능이다. 다른 스킬은 「어느 종류 + 카드에 무엇(그 분야 재료)」만 적고, 꼴은 여기를 따른다. 다른 스킬·도구에 적힌 꼴(크기·배치·번호·버튼)이 이 표준과 부딪히면 이 표준이 우선이다. 전용 도구가 만드는 페이지도 2.1을 따른다. **꼭** = 빠지면 사용자가 판단하기 어려워지는 것, 권장 = 있으면 좋은 것.

**네 종류 어디에도 안 맞으면** 종류에 끼우지 않는다. 2.1만 지키고, 「사용자가 이 페이지에서 무엇을 판단하나」를 먼저 한 줄로 쓴 뒤 그 판단에 맞는 꼴을 새로 짠다. 다른 종류의 칸은 맞는 것만 골라 빌린다. 채팅에 「표준에 없는 꼴이라 새로 짰어요」라고 알려 꼴 자체를 평받는다. 같은 꼴이 두 번째로 나오면 새 종류(2.x)로 올리자고 제안한다.

### 2.1 모든 페이지 — 꼭

**맨 위 「먼저 정해 주세요」**
- 사용자가 답할 것만 적는다. 질문마다 번호(1. 2.)를 붙이고, 질문 글자 자체를 그 답하는 자리로 가는 링크로 — 줄 끝에 「→ 1」 같은 링크를 따로 두지 않는다. 고르는 질문이면 중요도(핵심·중요·참고)와 「영향 범위 · 고르면 · 안 고르면」 세 줄을 그 질문 자리에 같이 둔다
- 답할 것이 없으면 그 자리에 「결론」으로 시작하는 한 줄(점검 스크립트가 이 글자를 찾는다) — 이때는 버튼·메모 칸·「추천대로 모두 고르기」를 두지 않는다
- **「추천대로 모두 고르기」** 버튼: 아직 답하지 않은 질문만 추천으로 채운다(이미 고른 보기·적어 둔 입력 칸은 그대로). 사용자는 그 뒤 바꿀 것만 다시 누른다
- 「채팅으로 답해도 됩니다」를 같이 쓴다

**답하는 칸**
- 보기마다 고르는 버튼을 그 질문 자리에 둔다
- 메모 칸은 질문마다 하나
- 보기 없는 질문(날짜·글)은 입력 칸만. 추천 답이 있으면 옆에 「추천: ○○」 버튼(누르면 칸을 채움, 2.6)
- 서버가 기록을 못 받으면(`GET /_pick` 404) 4절대로 다시 띄운다. 다시 띄울 수 없으면 버튼은 두되 맨 위에 「이 페이지는 기록되지 않아요 — 채팅으로 답해 주세요」

**번호** — 사용자가 「1은 A, 3 빼」처럼 집어 답할 수 있게
- 질문 = 1. 2., 보기 = A·B·C
- 따로 지칭할 카드(바뀐 곳·항목)는 질문과 따로 페이지 전체에서 1부터 이어서. 카드의 넣기/빼기는 기록(2.6)의 `q`를 `카드3`처럼 앞 글자를 붙여 질문 번호와 겹치지 않게 한다

**실제 모양으로**
- 그림·화면은 실제 캡처·시안
- 소리는 `<audio controls>`, 영상은 `<video controls>` — 파일 링크만 주지 않는다
- 그림은 크게, 누르면 화면 가득(←→, Esc)
- 비교 그림은 안마다 한 줄 전체 폭. 화면을 줄여 한 줄에 우겨 넣지 않는다

**그 밖**
- 경중은 [핵심]·[중요]·[참고] — 좋은 점·걸리는 점·위험·남은 일 같은 목록에
- 어두운 배경. HTML은 파일 하나(CSS·스크립트를 안에 넣고 외부 스크립트 없이), 그림·소리·영상은 옆 파일로 둔다

### 2.2 고르기 (보기 여럿 중 고름 — 시안·후보·목소리·방식)

꼭:
- 보기 하나 = 카드 하나. 카드엔 그 보기를 가르는 재료를 같이(예: 목소리 = 인물 그림 + 재생 + 읽힌 대사, UI 시안 = 실제 화면 + 상태 설명)
- 카드마다 좋은 점·걸리는 점(무게 표시)
- **추천 하나**: 카드는 주황 테두리 + 「추천」 글자(다른 후보를 흐리지 않음), 버튼도 같은 표시. 그 아래 **「추천 이유」 한두 문장** — 좋은 점이 걸리는 점보다 왜 무거운지, 본 곳(근거), 내 판단뿐이면 (추정). 「한다 / 안 한다」 버튼도 추천을 단다. 사용자만 아는 것(평가·취향·사실)을 묻는 질문엔 추천을 달지 않는다
- 이름 가린 비교(어느 모델·누가 만든 것인지 가린 페이지)엔 추천을 달지 않는다 — 추천이 가린 답을 알려 준다
- 고를 이유가 없는 보기는 만들지 않는다. 대체 수단뿐이면 「안 되면 ○○」 한 줄로

권장: 한 번에 2–3개(만들 때 돈·시간이 들면 2개 먼저)

### 2.3 바뀐 것 검수 (전·후 — 고친 판, 문서·노드·스키마·코드 변경)

꼭:

**카드 나누기**
- 카드 하나 = 바뀐 곳 하나. 사용자가 따로 넣거나 뺄 수 있는 단위로 나눈다
- 제목 앞 번호는 2.1 「번호」대로 페이지 전체에서 1, 2, 3…(「고침 N」 칸이 늘어도 이어서, 점 찍은 번호는 쓰지 않는다)
- 같은 대상(같은 파일·노드)의 카드는 대상 머리 하나 아래 묶는다
- 「그대로」는 맥락에 필요할 때만 회색 카드(버튼 없음)

**카드 머리**
- 번호 · 제목 · 대상 · (시간이 있는 것은 구간) · 무엇 · 왜
- 대상 = 파일·노드·화면이면 경로나 링크(앱 안의 대상이면 누르면 그 앱이 여는 주소) + 그게 무슨 일을 하는 것인지 한 줄
- 구간은 「0:31–0:34」처럼 시작–끝

**전·후**
- 머리 아래 한 줄에 전(왼쪽) · 후(오른쪽) 같은 폭
- 글이면 −/+ 줄 색
- 그림·영상이면 같은 자리를 바뀐 곳이 한눈에 보이는 크기로 잘라 나란히(전체 그림은 누르면 크게)
- 재생·이동 링크는 각 그림 바로 밑(카드 머리에 따로 두지 않음)
- 「전」은 바꾸기 전에 남겨 둔다(다른 에이전트에 맡길 때도 내가). 사용자가 스크린숏으로 지적하면 그 그림이 「전」

**표시와 버튼**
- 색 = 종류: 새로·만듦 초록 `#7ddc9a` · 고침 노랑 `#e5c84a` · 옮김 보라 `#b392f0` · 지움 빨강 `#f85149` · 그대로 회색. −/+ 줄도 같은 초록·빨강
- 선 = 상태: 아직 제안(승인 전) = 점선, 반영됨 = 실선
- 한 자리를 다른 것으로 바꿨으면(지움 + 새로) 고침
- 승인받는 페이지면 카드마다 「넣기 / 빼기」 버튼(추천 표시)

권장: 평을 받아 고친 판은 같은 페이지 맨 위에 「고침 N」 칸을 더함 · 넣지 않은 제안과 이유 한 줄
- 「고침 N」으로 다시 만들면 `round`를 새 시각으로 바꾼다 — 버튼은 빈 채로 시작하고, 지난 회차에 고른 것은 「고침 N」 칸에 한 줄(「지난번: 1 A, 3 빼기」)로 적는다

칸이 많은 대상(DB 스키마처럼 표 하나에 칸 수십 개): 카드 = 표 하나, 전후는 좌우 두 판 대신 칸마다 그대로/새로/고침(전 → 후)/지움 표시로 한 판에. 좌우로 놓으면 바뀐 칸 몇 개를 찾기 어렵다. 넣기/빼기는 표 단위, 표마다 용도 한 줄을 버튼보다 먼저

### 2.4 계획 (작업 순서·단계) (시험 중)

꼭:
- 단계는 원래 순서대로, 단계마다 「정함 / 가정(확인 안 함) / 정해 주실 것」 표시와 근거(본 곳)
- 「정해 주실 것」은 그 단계 자리에 답하는 칸, 맨 위 「먼저 정해 주세요」엔 번호와 링크
- 원래 계획(대화·문서)의 단계 하나 = 항목 하나 — 단계는 번호·글머리표 한 줄, 표면 행 하나로 센다(설명 문단은 단계가 아님). 맨 아래 「원래 n개 → 페이지 n개, 합친 것·뺀 것」 한 줄
- 날짜·기간·진행률·「완료」는 원래 계획에 있거나 이번 대화에서 확인한 것만. 순서·의존 화살표도 실제로 있을 때만
- 내가 묶거나 순서를 바꾸거나 더한 단계는 채팅에도 한 줄

### 2.5 결과·설명 (조사 결과·분석·보고 한 장)

꼭:
- 첫 화면에 결론
- 글로 말한 것은 본 화면(스크린숏·프레임 시트·그래프)을 옆에. 한 화면이 여러 조각이면 한 장으로 붙여서
- 숫자 흐름은 그래프(png 또는 그림), 표만 주지 않음

### 2.6 고른 것 기록 — 고르는 칸이 있는 페이지 공통 (시험 중)

고르는 페이지는 질문(카드)마다 고르는 버튼과 메모 칸을 둔다. 보기가 없는 질문(날짜·글)은 입력 칸만 두고 적은 글이 답이다. 버튼을 누를 때와 메모를 고칠 때 `/_pick`에 `{page: decodeURIComponent(location.pathname), round, q, choice, note}`를 POST하고 「기록됨」을 보인다(메모를 고치면 다시 보내기 전까지 「기록됨」을 지운다). `round`는 페이지를 만들 때 넣는 시각, `q`는 「먼저 정해 주세요」의 번호(카드 넣기/빼기는 `카드N`, 2.1 「번호」). 4절 서버가 그 페이지 폴더의 `_picks.jsonl`에 한 줄씩 남긴다. 남는 `page`는 서버 폴더 기준 경로에서 앞 `/`를 뗀 디코딩된 글자다(예: `2026-11-21_비교.html`, 하위 폴더면 `시안/2026-11-21_비교.html`). 「채팅으로 답해도 됩니다」를 같이 쓴다. 서버 주소로 열어야 기록된다(`file://`은 안 됨). 틀: [scripts/pick_example.html](scripts/pick_example.html)
  - 사용자가 다음에 답하면 `_picks.jsonl`을 한 줄씩 JSON으로 읽어(안 읽히는 줄은 건너뛰고 몇 줄인지 한 마디) page와 round가 이번 것인 줄만 골라 q마다 마지막 줄을 답으로 친다. 채팅 답과 합치고, 둘이 다르면 채팅이 우선이고 다르다고 한 줄 말한다. 채팅에서 말하지 않은 q는 기록 줄을 쓰되 「페이지에서 고른 것: …」으로 밝힌다
- 버튼 값은 `data-v`에 따로 둔다 — 표시 글자(「추천」 등)가 기록에 섞이지 않게
- 보기 없는 질문의 상자는 `data-kind="input"`으로 표시한다 — 표시 글자(「추천:」)로 가르지 않는다. 그 「추천: ○○」 버튼은 `class="rec fill"`(「 추천」 꼬리표가 안 붙음)
- 보기를 안 골라도 메모만 고치면 기록한다(choice는 null)
- 기록 시험은 페이지 복사본을 다른 폴더에 두고 한다 — 사용자가 이미 누른 `_picks.jsonl`을 지우지 않게

## 3. 띄우는 곳

- **페이지를 두는 곳**: 프로젝트(작업 폴더) 안의 `review-pages/` 폴더에 `<날짜>_<주제>.html`로, 그 페이지가 쓰는 그림·소리도 같은 폴더(또는 그 아래)에 둔다 — 서버는 한 폴더만 보여 주므로 밖에 있는 파일은 안 열린다. 프로젝트 지침이 다른 폴더를 정했으면 그것을 따른다. 그림·소리를 git에 넣지 않을 거면 이 폴더를 `.gitignore`에
- **기본**: 서버는 그 `review-pages/` 폴더를 열고(4절) 포트는 8765(4절 「포트 고르기」). 로컬 서버 주소 `http://127.0.0.1:<포트>/<퍼센트 인코딩 경로>`를 채팅에 준다. 주기 전에 `python <이 스킬 폴더>/scripts/check_page.py <주소> <png>`를 돌린다(선택 — playwright가 깔려 있을 때. `-I`를 붙이지 않는다: 사용자 영역에 깔린 playwright를 못 찾는다) — 열림·콘솔 오류·못 불러온 파일·가로 넘침·「먼저 정해 주세요」(없으면 「결론」 한 줄)가 첫 화면에 있나·고르는 추천 버튼이 있으면 「추천 이유」가 있나·추천이 질문마다 하나 이하인가·페이지 안 링크가 있는 자리를 가리키나·고른 것 기록 서버인가를 본다. 종료 코드 1이면 고친 뒤 다시, 2(도구가 못 돎)면 200만 확인하고 채팅에 「점검 도구 못 돌림: 이유」 한 줄. 남긴 png는 직접 열어 본다. 상대 링크·`file:///`는 IDE에서 코드로 열려서 쓰지 않는다. 에이전트가 브라우저 창을 직접 띄우지 않는다 — 사용자가 모르는 창을 닫아 버린다. 예외: 사용자가 큰 화면으로 보겠다고 하면 기본 브라우저로 띄운다(파일 경로가 아니라 서버 주소로)
- **작업하는 앱에 브라우저 패널이 있으면**(편집기·지식 관리 앱 등): 같은 HTML을 그 패널에 연다. 페이지 안에서 앱 안의 대상(클립·노드)으로 가는 링크는 그 앱이 주는 주소를 쓴다. 앱 전용 주소가 든 페이지는 채팅에 주소를 쓰지 않고 「앱 브라우저에 띄워 뒀어요」만 쓴다 — 채팅에서는 그 주소가 안 열린다. 앱 주소가 없는 페이지는 채팅에도 주소를 준다. 앱에 탭이 여럿이면 사용자가 보는 탭이 아닌 곳에 열었을 때 어느 탭인지 같이 말한다
- **사용자가 그 주소를 열 수 없으면**(원격·클라우드에서 도는 에이전트 등 — `127.0.0.1`은 에이전트가 도는 컴퓨터를 가리킨다): 서버 없이 HTML 파일 하나를 그 환경의 파일 전달·미리보기 기능으로 넘긴다. 고른 것 기록이 안 되니 맨 위에 「채팅으로 답해 주세요」를 쓰고 답은 채팅으로 받는다

## 4. 서버

- `python -I <이 스킬 폴더>/scripts/serve_pages.py <폴더> <포트>` — 정적 파일 서버, 오디오·영상 위치 이동(Range)이 된다. `/_pick`으로 고른 것을 기록한다(2.6). 표준 라이브러리만 써서 `-I`로 돌린다. 이 문서의 `python`은 macOS·Linux에서 `python3`으로 바꿔 쓴다
- **포트 고르기**: 8765부터. 그 포트에 이번 페이지 주소를 요청해
  - 200이고 `GET /_pick`도 200 → 같은 폴더를 보여 주는 서버가 이미 떠 있음, 그대로 쓴다
  - 200인데 `/_pick`이 404 → 기록 기능이 없는 옛 판, 끄고 그 포트에 다시 띄운다
  - 404이거나 다른 것이 응답 → 다른 폴더(다른 프로젝트)의 서버다. 끄지 않고 다음 포트(8766, 8767…)로 같은 확인을 한다 — 끄면 사용자가 다른 곳에서 보던 페이지가 죽는다
  - 응답 없음 → 그 포트에 새로 띄운다
- **띄운 뒤 확인**: 숨겨 띄운 서버는 포트가 이미 쓰이고 있으면 말없이 죽는다. 띄운 뒤 1–2초 기다려 이번 페이지 주소가 200인지 보고 나서 주소를 준다
- **오래 띄우기**: 에이전트 도구의 백그라운드 명령으로 띄우면 그 명령의 시간 제한이 지나면 꺼질 수 있다. 에이전트 명령과 떨어진 프로세스로 띄운다. 창은 만들지 않는다 — 콘솔 창이 뜨면 사용자가 닫아 서버가 죽는다
  - Windows(PowerShell): `Start-Process -FilePath python -ArgumentList '-I "<이 스킬 폴더>/scripts/serve_pages.py" "<폴더>" <포트>' -WindowStyle Hidden` — 명령이 끝나도, 세션이 끝나도 산다. 인자는 문자열 하나에 경로마다 큰따옴표로 — `'-I','<경로>',…`처럼 나눠 주면 경로에 빈칸이 있을 때 말없이 죽는다
  - 띄운 뒤 200이 안 나오면 같은 명령을 숨기지 않고(`python -I <이 스킬 폴더>/scripts/serve_pages.py <폴더> <포트>`) 한 번 돌려 오류를 본다
  - macOS·Linux: `nohup python3 -I <이 스킬 폴더>/scripts/serve_pages.py <폴더> <포트> >/dev/null 2>&1 &`
- 끄기: 그 포트를 듣는 프로세스를 찾아 끈다(Windows `Get-NetTCPConnection -LocalPort <포트> -State Listen` → `Stop-Process`, macOS·Linux `lsof -ti tcp:<포트> -sTCP:LISTEN | xargs kill`)
